1. INTRODUCCIÓN
================================================================================

La presente Especificación de Requisitos de Software (SRS v2.0) formaliza de manera 
rigurosa, estructurada y verificable el conjunto de capacidades funcionales, 
atributos de calidad y restricciones operativas del Sistema Informático de Gestión 
Clínica y Comercial Optométrica (SGO), desarrollado para el establecimiento de salud 
visual Óptica Vista Visión, radicado en la ciudad de Riobamba, Provincia de Chimborazo.

1.1 PROPÓSITO
El propósito de este documento es:
a) Establecer la línea base técnica contractual y de ingeniería de software definitiva 
   para el diseño de la base de datos relacional, la arquitectura de microservicios y 
   la implementación en Sprints ágiles bajo la metodología Scrum.
b) Servir de insumo primario e indispensable para la elaboración del Estudio de 
   Factibilidad (`ESTUDIO DE FACTIBILIDAD/directrices.txt`), fundamentando sus análisis 
   en las dimensiones técnica, económica, legal y operativa.
c) Consolidar formalmente los dos nuevos requisitos estratégicos aprobados:
   1. Facturación Electrónica con los Web Services del Servicio de Rentas Internas (SRI).
   2. Componente de Innovación Tecnológica: Asistente Inteligente Operativo "Chatbot con los Datos".
d) Establecer los criterios formales de verificación de seguridad conforme al estándar 
   ISO/IEC 25010:2023 y el marco Secure Scrum (Pohl y Hof, 2015).
Audiencia: Tribunal académico de titulación de la ESPOCH, director y asesor del proyecto, 
equipo de desarrollo (backend/frontend) y personal directivo de Óptica Vista Visión.

1.2 ALCANCE
- Denominación del producto: Sistema Informático de Gestión Clínica y Comercial Optométrica (SGO).
- Descripción del sistema: Aplicación web responsiva de alta seguridad concebida bajo una 
  arquitectura desacoplada. Integra el control integral de pacientes, refracción clínica 
  asistida con validaciones dioptricas automáticas, emisión de órdenes técnicas para talleres 
  ópticos externos con aislamiento de datos sensibles (cumplimiento LOPDP), ventas de mostrador, 
  arqueo diario de caja, facturación electrónica nativa con el SRI y asistencia inteligente 
  operativa mediante consultas en lenguaje natural con blindaje estricto de solo lectura.
- Delimitación de los Siete Módulos Funcionales:
  * Módulo 1 (M1): Autenticación y Gestión de Usuarios
  * Módulo 2 (M2): Gestión de Pacientes
  * Módulo 3 (M3): Historia Clínica y Graduación
  * Módulo 4 (M4): Pedidos al Laboratorio Óptico
  * Módulo 5 (M5): Ventas y Cobros Locales
  * Módulo 6 (M6): Facturación Electrónica SRI (Firma XAdES-BES, SOAP, RIDE PDF y Correo)
  * Módulo 7 (M7): Asistente Inteligente Operativo "Chatbot con los Datos" (Consultas Seguras)

1.4 DEFINICIONES, ACRÓNIMOS Y ABREVIATURAS
- ACID: Atomicidad, Consistencia, Aislamiento y Durabilidad (garantías de persistencia relacional).
- ATS: Anexo Transaccional Simplificado (reporte tributario oficial exigido por el SRI).
- Clave de Acceso: Código numérico único de 49 dígitos con dígito verificador Módulo 11 para comprobantes SRI.
- CQRS: Command Query Responsibility Segregation (patrón arquitectónico de separación comando/consulta).
- DNP / DP: Distancia Nasopupilar / Distancia Interpupilar en milímetros (mm).
- EventBus: Bus de eventos de dominio para comunicación reactiva asíncrona entre módulos.
- IEEE: Institute of Electrical and Electronics Engineers.
- ISO/IEC 25010:2023: Norma internacional de calidad y evaluación de producto software.
- JWT: JSON Web Token (estándar abierto RFC 7519 para intercambio seguro de credenciales).
- LLM: Large Language Model (modelo de lenguaje masivo para procesamiento de lenguaje natural).
- LOPDP: Ley Orgánica de Protección de Datos Personales del Ecuador (Registro Oficial 459, 2021).
- NLP: Natural Language Processing (procesamiento de lenguaje natural para el enrutamiento de intenciones).
- PKCS#12 (.p12): Formato de contenedor criptográfico para almacenar llaves privadas y certificados X.509.
- RBAC: Role-Based Access Control (control de acceso basado en roles).
- RIDE: Representación Impresa de Documento Electrónico (formato PDF oficial regulado por el SRI).
- SGO: Sistema de Gestión Optométrica.
- SOAP: Simple Object Access Protocol (protocolo de intercambio XML sobre HTTP empleado por los Web Services del SRI).
- Soft Delete: Borrado lógico mediante marcado temporal inactivo (`deleted_at`).
- S-Tag: Secure Scrum Security Tag (etiqueta formal de trazabilidad de requisitos de seguridad).
- XAdES-BES: XML Advanced Electronic Signatures - Basic Electronic Signature (perfil oficial de firma digital en Ecuador).

2.1 PERSPECTIVA DEL PRODUCTO
El Sistema de Gestión Optométrica (SGO) es una solución integral, autónoma y distribuida 
diseñada para modernizar y blindar operacionalmente a Óptica Vista Visión. Su arquitectura 
se organiza en servicios especializados y desacoplados:
- Capa de Presentación (Frontend): Single Page Application (SPA) responsiva en React con Vite, 
  diseñada bajo criterios de ergonomía clínica y equipada con un widget interactivo para el asistente de IA.
- Núcleo Transaccional Clínico-Comercial (Backend Core): API RESTful desarrollada sobre el 
  framework Laravel 10+, encargada de la lógica clínica, recetas, órdenes técnicas, inventario y caja.
- Microservicio de Facturación Electrónica (API SRI): Microservicio empresarial desarrollado en 
  NestJS con TypeScript, TypeORM, CQRS y arquitectura orientada a eventos (EDA). Ejecuta el ciclo 
  completo de emisión XML v1.1.0, firma digital avanzada XAdES-BES, enlace SOAP con el SRI, 
  generación de RIDE en PDF vía Puppeteer y despacho por correo vía SMTP.
- Motor del Asistente Inteligente ("Chatbot con los Datos"): Servicio híbrido acoplado a un 
  enrutador de intenciones léxico-sintáctico (Regex/plantillas determinísticas para modo LAN local) 
  y conector opcional a modelos LLM para contextualización comercial, conectado a PostgreSQL bajo 
  un rol exclusivo de solo lectura (`GRANT SELECT`).
- Capa de Persistencia: Base de datos relacional PostgreSQL 16 con soporte transaccional ACID, 
  auditoría completa (`audit_logs`) y aislamiento de esquemas.

2.2 FUNCIONALIDAD DEL PRODUCTO
El sistema implementa de forma integrada siete módulos funcionales:
1. Módulo de Autenticación y Gestión de Usuarios: Registro de operadores, control granular RBAC 
   (Administrador, Optometrista, Asistente) y gestión segura de sesiones con tokens JWT firmados.
2. Módulo de Gestión de Pacientes: Registro demográfico, validador de cédula ecuatoriana módulo 10 
   con búsqueda predictiva anti-duplicados, soporte flexible para menores de edad y repositorio seguro de adjuntos.
3. Módulo de Historia Clínica y Graduación: Examen refractivo independiente OD/OI (Esfera, Cilindro negativo, 
   Eje, Adición con signo positivo forzado, DP/DNP, Snellen pies), parámetros de montura, anamnesis CIE-10, 
   comparativa dinámica lente previo, emisión de certificados/recetas en PDF e inmutabilidad mediante Soft Delete.
4. Módulo de Pedidos al Laboratorio Óptico: Órdenes de trabajo técnicas desprovistas de diagnósticos 
   confidenciales (LOPDP), catálogo dinámico de lunas y tratamientos, máquina de estados finitos (4 estados) 
   y control de garantías/rectificaciones.
5. Módulo de Ventas y Cobros Locales: Emisión de comprobantes internos de venta, control híbrido de 
   stock (lotes de armazones por precio y unitario para consumibles), cobros mixtos con anticipos/saldos 
   bajo transacciones ACID y arqueo consolidado de caja diaria.
6. Módulo de Facturación Electrónica SRI: Construcción automatizada de XML oficial, cálculo algorítmico 
   de clave de acceso de 49 dígitos (Módulo 11), firma digital XAdES-BES con certificado PKCS#12, 
   transmisión y consulta SOAP (RecepcionComprobantesOffline / AutorizacionComprobantesOffline), 
   renderizado de RIDE PDF con código de barras Code128, despacho de correo y generación de ATS mensual.
7. Módulo del Asistente Inteligente Operativo ("Chatbot con los Datos"): Interfaz conversacional 
   en Dashboard para consultas en lenguaje natural sobre finanzas de caja, existencias de armazones y 
   pedidos de taller pendientes, con filtro estricto por roles RBAC, modo autónomo LAN offline y solo lectura inviolable.

2.4 RESTRICCIONES DE DISEÑO E IMPLEMENTACIÓN
1. Restricción de Alcance y Tiempo: Desarrollo estructurado en 4 Sprints quincenales (8 semanas calendario).
2. Restricción Tecnológica: Frontend en React 18, Backend Core en Laravel 10+, Microservicio SRI en 
   NestJS 10+ con TypeScript, Gestor de Base de Datos PostgreSQL 16+.
3. Restricción Criptográfica y de Certificación: Uso estricto de certificados digitales PKCS#12 (.p12) 
   válidos emitidos por entidades certificadoras acreditadas en Ecuador; prohibición de almacenar 
   contraseñas de firma en texto claro en repositorios.
4. Restricción de Inviolabilidad de Datos en IA: Conexión exclusiva de solo lectura (`GRANT SELECT`) 
   para el servicio del chatbot, garantizando la imposibilidad matemática de modificaciones accidentales.
5. Restricción de Privacidad y Normativa Sanitaria: Cumplimiento imperativo de la Ley Orgánica de 
   Protección de Datos Personales (LOPDP Ecuador), aislando historiales patológicos de las órdenes enviadas a laboratorios.
6. Restricción de Autonomía Local: El sistema clínico debe ser 100% operativo en la red LAN del consultorio, 
   asegurando que caídas de internet no impidan la atención a pacientes ni la venta de mostrador.

2.5 SUPOSICIONES Y DEPENDENCIAS
1. Conectividad Externa: Se asume servicio de internet en consultorio para la transmisión SOAP hacia el 
   SRI, despacho de correos SMTP y modo contextual del chatbot; en caso de corte, el sistema conmuta a 
   modo contingencia offline.
2. Certificado Digital Vigente: Se asume que el emisor dispone de un certificado .p12 legalmente emitido y con vigencia activa.
3. Compatibilidad de Navegadores: Clientes ejecutados en Google Chrome, Mozilla Firefox, Microsoft Edge o Safari con ES6+.
4. Entorno de Impresión: Disponibilidad de impresoras térmicas de 80 mm para recibos locales e impresoras láser/inyección para RIDE y recetas A4.

2.6 EVOLUCIÓN PREVISIBLE DEL SISTEMA (REQUISITOS FUTUROS)
Habiéndose integrado la Facturación Electrónica SRI y el Chatbot de Innovación en esta Versión 2.0, 
el catálogo de requisitos futuros se redefine para fases post-titulación:
- RF-FUT-01: Notificaciones y envío automatizado de RIDE/recetas por WhatsApp Business Cloud API.
- RF-FUT-02: Pipeline ETL para migración histórica de datos desde el archivo .BAK de SQL Server del software legado.
- RF-FUT-03: Módulo de Agenda Médica con reservas en línea y recordatorios de turnos vía SMS/Web.
- RF-FUT-04: Transacciones del Chatbot con Confirmación en Doble Factor (escritura asistida para reajuste de precios y bajas de stock).

3.1 REQUISITOS COMUNES DE LAS INTERFACES

3.1.1 Interfaces de Usuario
- Interfaz web Single Page Application (SPA) con arquitectura responsiva y navegación ergonómica.
- Formularios optométricos en cuadrícula simétrica para OD y OI con desplazamiento fluido por teclado (Tab/Enter).
- Pantalla dedicada para Facturación Electrónica con visualización de estado en tiempo real (AUTORIZADO, EN PROCESO, DEVUELTA), 
  descarga de XML firmado y visualizador embebido del RIDE en PDF.
- Widget flotante en esquina inferior del Dashboard para interacción conversacional con el Asistente Inteligente ("Chatbot con los Datos"), 
  con presentación de respuestas enriquecidas mediante tarjetas de resumen y badges de estado.

3.1.2 Interfaces de Hardware
- Compatibilidad con PCs de escritorio y portátiles (mínimo CPU Intel Core i3 / AMD Ryzen 3, 8 GB RAM).
- Soporte para tabletas táctiles (mínimo 1024x768 de resolución) para captura clínica en consultorio.
- Impresoras térmicas de tickets POS (80 mm) e impresoras multifunción estándar (A4/Carta) para RIDE y recetas.

3.1.3 Interfaces de Software
- Motor de Base de Datos PostgreSQL 16+ con soporte JSONB y transacciones ACID.
- API Core en Laravel 10+ (PHP 8.2) comunicada vía REST JSON.
- Microservicio API-SRI en NestJS 10+ (Node.js 20+ LTS, TypeORM, @nestjs/cqrs).
- Motor de Firma Digital: Librería 'node-forge' para parsing PKCS#12, canonicalización XML-C14N y digest SHA-1.
- Generación de RIDE: Librería 'bwip-js' (código de barras Code128) y 'puppeteer' (renderizado PDF headless).
- Servicio de Correo: 'nodemailer' con transporte SMTP cifrado TLS/SSL.
- Conector de IA: Cliente HTTP seguro (Axios/cURL) para invocación de API LLM en modo aumentado.

3.1.4 Interfaces de Comunicación
- Protocolo de transporte HTTPS con cifrado obligatorio TLS 1.2 / TLS 1.3 en todas las conexiones cliente-servidor.
- Comunicación SOAP 1.1 / 1.2 sobre HTTP con los Web Services oficiales del SRI:
  * Pruebas: `https://celcer.sri.gob.ec/comprobantes-electronicos-ws/...`
  * Producción: `https://cel.sri.gob.ec/comprobantes-electronicos-ws/...`
- Intercambio de cargas útiles de datos en formato UTF-8 JSON entre React, Laravel y NestJS.

3.3 REQUISITOS NO FUNCIONALES (ISO/IEC 25010:2023 Y S-TAGS)

3.3.1 Rendimiento
- RNF-08 (Eficiencia de Tiempos de Respuesta):
  Las búsquedas predictivas de pacientes, historiales y resúmenes de caja diaria 
  deben retornar en menos de 1.5 segundos en la red local. Las consultas operativas 
  resueltas por el Asistente Inteligente en Modo LAN deben responder en un tiempo inferior a 1.0 segundo.
- Capacidad Transaccional: El microservicio de Facturación Electrónica debe procesar 
  la firma digital XAdES-BES en memoria en un tiempo medio inferior a 400 milisegundos.

3.3.2 Seguridad de la Información (Alineada a ISO/IEC 25010:2023 y S-Tags)
- RNF-01 [S-TAG-AUTH-01] (Autenticidad por Roles):
  Verificación inequívoca de identidad mediante contraseñas cifradas con bcrypt (costo 12) 
  y asignación estricta de privilegios RBAC en endpoints de Laravel y NestJS.
- RNF-02 [S-TAG-AUTH-02] (Gestión Criptográfica de Sesiones):
  Intercambio protegido por tokens JWT (RFC 7519) con firma criptográfica HMAC-SHA256 y vencimiento a 20 min.
- RNF-03 [S-TAG-INT-01] (Integridad en Validación Dual):
  Validación simétrica en cliente (React) y backend (FormRequests) para rangos dióptricos 
  (pasos de 0.25, cilindro negativo obligatorio y adición positiva forzada).
- RNF-04 [S-TAG-INT-02] (Integridad Relacional y Transaccional):
  Transacciones ACID con aislamiento READ COMMITTED en PostgreSQL para ventas, cobranzas y movimientos de stock.
- RNF-05 [S-TAG-INT-03] (Inmutabilidad Clínica):
  Historiales médicos inalterables; prohibición de sobreescritura; adopción de borrado lógico (Soft Delete).
- RNF-06 [S-TAG-RES-01] (Responsabilidad y Trazabilidad General):
  Tabla inmutable `audit_logs` que captura user_id, timestamp UTC, dirección IP, tipo de evento, 
  tabla afectada y estados anterior vs. nuevo en formato JSONB.
- RNF-10 [S-TAG-AUTH-03, S-TAG-RES-02] (Seguridad Criptográfica y Firma Electrónica SRI):
  Custodia estricta en memoria de contraseñas de certificados digitales .p12 durante la 
  firma digital XAdES-BES, impidiendo el almacenamiento de claves privadas en texto claro o variables expuestas.
- RNF-11 [S-TAG-INT-06] (Blindaje Transaccional de Inteligencia Artificial):
  Aislamiento irrestricto de solo lectura para el asistente conversacional, vetando cualquier 
  posibilidad de modificación o corrupción de datos clínicos y contables.

3.3.3 Fiabilidad y Tolerancia a Fallos
- RNF-09 (Resiliencia Asíncrona ante Caídas del SRI):
  El sistema debe desacoplar el cobro de la venta local de la autorización fiscal externa. 
  Si los Web Services del SRI presentan caídas o intermitencias, el comprobante se almacena 
  en estado 'EN PROCESO' o 'PENDIENTE' para retransmisión asíncrona mediante tareas programadas (Crons).
- Recuperabilidad: Respaldos automáticos diarios de la base de datos PostgreSQL mediante pg_dump.

3.3.4 Disponibilidad y Resiliencia Operativa
- Disponibilidad mínima del 99.5% durante el horario de atención de la óptica (lunes a sábado, 08:00 a 19:00).
- Autonomía Local: Operatividad completa en red LAN para atención clínica, emisión de recetas, 
  pedidos de taller, ventas y cobros locales, aun ante la pérdida total de acceso a internet.

3.3.5 Mantenibilidad y Modularidad
- Separación limpia entre capas (Frontend React, API Core Laravel, Microservicio NestJS y PostgreSQL).
- Código tipado estricto en TypeScript y cumplimiento de estándares PSR-12 en PHP.

3.3.6 Portabilidad y Usabilidad
- RNF-07 (Soporte Multiplataforma y Diseño Responsivo):
  Interfaz web responsiva con soporte en computadoras de escritorio y tabletas táctiles 
  en navegadores modernos (Chrome, Firefox, Edge, Safari).


3.4 OTROS REQUISITOS

3.4.1 Requisitos Legales y Normativos
- Cumplimiento de la Ley Orgánica de Protección de Datos Personales (LOPDP Ecuador):
  Aislamiento estricto de la historia clínica en órdenes emitidas a talleres de lentes externos.
- Ficha Técnica de Comprobantes Electrónicos Esquema Offline v1.1.0 del SRI:
  Estructura XSD, Clave de Acceso Módulo 11 y formato oficial de RIDE.
- Ley de Comercio Electrónico y Firmas Digitales:
  Validez jurídica del firmado digital XAdES-BES mediante certificados válidos emitidos en Ecuador.

3.4.2 Requisitos Operativos, Fiscales y de Entorno Local
- Moneda oficial: Dólares de los Estados Unidos de América (USD).
- Formato regional de fechas: dd/mm/aaaa.
- Tarifa de Impuesto al Valor Agregado (IVA): Parametrizable conforme a la tasa legal vigente (15% general / 0% tarifa cero).
- Restricción de Consumidor Final: Emisión máxima hasta 40.00 USD según resolución tributaria vigente del SRI.

APÉNDICE C: GLOSARIO TÉCNICO EXTENDIDO
--------------------------------------------------------------------------------
- Agudeza Visual (AV): Capacidad del sistema visual para discriminar detalles espaciales a distancia dada.
- Anamnesis: Interrogatorio clínico sobre antecedentes patológicos y síntomas del paciente.
- Anexo Transaccional Simplificado (ATS): Formato XML oficial del SRI para compras, ventas y retenciones.
- Astigmatismo: Defecto refractivo en que los rayos de luz divergen debido a la asimetría corneal.
- Autorización SRI: Acto tributario formal en que el SRI valida y sella electrónicamente una factura.
- Clave de Acceso: Secuencia alfanumérica de 49 dígitos que identifica inequívocamente al comprobante fiscal.
- Dioptría (D): Unidad cuantitativa que expresa el poder de refracción de una lente óptica.
- Distancia Nasopupilar (DNP): Medida milimétrica desde el centro de la pupila hasta el tabique nasal.
- Formato PKCS#12: Estándar para archivar objetos criptográficos en un solo archivo protegido con contraseña.
- Large Language Model (LLM): Modelo de inteligencia artificial entrenado para interpretar y generar texto natural.
- Presbicia: Condición fisiológica vinculada a la edad que reduce progresivamente la visión cercana.
- RIDE: Representación Impresa de Documento Electrónico en formato PDF regulada por la autoridad tributaria.
- Soft Delete: Mecanismo de persistencia que oculta un registro asignándole fecha de borrado sin eliminarlo físicamente.
- Transposición Óptica: Procedimiento matemático para transformar una fórmula esferocilíndrica positiva a cilindro negativo.
- XAdES-BES: Esquema de firma XML con estampado de tiempo y referencias criptográficas que garantiza autenticidad y no repudio.
