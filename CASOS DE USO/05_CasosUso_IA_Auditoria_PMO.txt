4. RESUMEN EJECUTIVO (PAQUETE M7 Y AUDITORÍA)
================================================================================

4.1 PROCESOS DE CONSULTA INTELIGENTE Y ANALÍTICA OPERATIVA
El Paquete 7 (M7) incorpora un Asistente Conversacional Inteligente integrado en la 
interfaz gráfica del sistema SGO. Su objetivo es brindar al personal del centro óptico 
acceso instantáneo a métricas operativas, disponibilidad de existencias, seguimiento de 
trabajos de laboratorio y consolidaciones financieras sin requerir la navegación manual 
por menús o la construcción de reportes complejos.

4.2 PRINCIPIO DE AISLAMIENTO DE SOLO LECTURA (READ-ONLY GUARD)
Para mitigar riesgos de inyección de comandos o modificaciones accidentales de la base 
de datos mediante lenguaje natural (prompt injection o jailbreaks), el sistema implementa 
un guardián de solo lectura a nivel arquitectónico:
1. Conexión de Base de Datos Restringida: El microservicio de IA se conecta a PostgreSQL 
   utilizando un usuario que posee exclusivamente privilegios `GRANT SELECT`. Cualquier 
   sentencia `INSERT`, `UPDATE`, `DELETE` o `DROP` es abortada inmediatamente a nivel de motor.
2. Filtro Léxico y RBAC: Un enrutador determinístico analiza los claims JWT del usuario 
   autenticado antes de formular la consulta, impidiendo que el personal de recepción 
   consulte balances financieros reservados a la gerencia.

4.3 MARCO DE AUDITORÍA INMUTABLE TRANSVERSAL (S-TAG-ACC)
Todo evento ejecutado a través del asistente inteligente o de los módulos clínicos y 
comerciales es registrado de forma atómica en la tabla `audit_logs`. Cada asiento 
incorpora un hash encadenado (Hash Chain) que vincula criptográficamente el registro 
actual con el precedente, garantizando la detección inmediata de cualquier adulteración 
forense de las pistas de auditoría.

7.1 CASO DE USO: CU-IA-01 — CONSULTAR MÉTRICAS EN LENGUAJE NATURAL
================================================================================
Caso de Uso:        Consultar Métricas y Existencias en Lenguaje Natural (Read-Only Guard)
Identificador:      CU-IA-01
Actores:            Usuario Autenticado (ACT-01, ACT-02, ACT-03), Motor IA (ACT-SIS-01).
Tipo:               Secundario / Analítica
Referencias:        SRS v2.0: RF-28, RF-29, RF-30, RF-31.
                    Reglas de Negocio: RN-IA-01, RN-IA-02.
                    Seguridad: S-TAG-AUTH-05, S-TAG-INT-08, S-TAG-ACC-08 (ISO/IEC 25010).
Precondición:       1. Usuario autenticado con token JWT válido.
                    2. Widget del asistente conversacional desplegado en el Dashboard.
Postcondición:      1. Respuesta estructurada proyectada en la interfaz de chat en < 800 ms.
                    2. Tarjetas informativas interactivas con enlaces rápidos mostradas.
                    3. Ninguna tabla de la base de datos es alterada (Cero escrituras).
                    4. Registro inmutable de la consulta y respuesta almacenado en `audit_logs`.
Descripción:        Permite formular preguntas operativas en lenguaje natural (ej. "¿Cuántos 
                    armazones metálicos semialaire tenemos en stock?", "¿Qué órdenes de taller 
                    deben entregarse el viernes?", "¿Cuál es el arqueo recaudado en caja hoy?"). 
                    El sistema valida los permisos RBAC del usuario, analiza léxicamente la 
                    intención, consulta la base de datos a través de una conexión de solo lectura 
                    estricta y retorna la respuesta redactada junto con tarjetas visuales de apoyo.
Resumen:            El usuario escribe una consulta en el chat; el sistema verifica sus privilegios; 
                    bloquea cualquier intento de modificación; consulta la base de datos en modo 
                    lectura; devuelve los datos formateados y registra la auditoría.

7.2 CASO DE USO: CU-AUD-01 — REGISTRO TRANSVERSAL DE AUDITORÍA Y NO REPUDIO
================================================================================
Caso de Uso:        Registro Transversal Inmutable de Auditoría y No Repudio
Identificador:      CU-AUD-01
Actores:            Sistema SGO (Actor Transversal Automático), Administrador (ACT-01).
Tipo:               Primario / Seguridad Transversal
Referencias:        SRS v2.0: RF-31.
                    Seguridad: S-TAG-ACC-01 a S-TAG-ACC-08 (ISO/IEC 25010:2023).
Precondición:       Cualquier evento de dominio transaccional ejecutado en el sistema 
                    (login, creación de paciente, venta, sellado de receta, anulación o IA).
Postcondición:      1. Asiento persistido en la tabla `audit_logs` con sello de tiempo UTC.
                    2. Hash criptográfico encadenado calculado ($Hash_n = \text{SHA-256}(Hash_{n-1} + Registro_n)$).
                    3. Registro protegido contra modificación o borrado mediante triggers de BD.
Descripción:        Provee el mecanismo centralizado de auditoría y no repudio del sistema SGO. 
                    Cada operación sensible registra el usuario responsable, su rol, la 
                    dirección IP de origen, el agente de usuario, el valor previo y el valor nuevo. 
                    La tabla implementa un encadenamiento criptográfico que imposibilita la 
                    alteración manual de bitácoras por parte de administradores o atacantes.
Resumen:            El sistema captura el evento disparado por cualquier caso de uso; recopila 
                    metadatos de red y usuario; calcula el hash criptográfico encadenado; 
                    inserta el registro inmutable y garantiza la trazabilidad legal del software.

CURSO NORMAL (Flujo Básico):
+------+-----------------------+-----------------------------------------------------------------+
| Paso | Ejecutor              | Actividad o Paso del Proceso                                    |
+------+-----------------------+-----------------------------------------------------------------+
| 1    | Sistema SGO           | Intercepta el evento de dominio exitoso (ej. `VentaCreada`).    |
| 2    | Sistema SGO           | Extrae los metadatos de contexto:                               |
|      |                       | - `user_id` del token JWT activo.                               |
|      |                       | - Dirección IP del cliente y User-Agent del navegador.          |
|      |                       | - Marca temporal de alta precisión en UTC (`TIMESTAMPTZ`).      |
|      |                       | - Tipo de Evento / Módulo (ej. 'VENTAS_COBRO_ANTICIPO').        |
|      |                       | - Datos de la transacción (JSON con valores anteriores/nuevos). |
| 3    | Sistema SGO           | Recupera el hash criptográfico del último registro de auditoría |
|      |                       | persistido en la tabla (`previous_hash`).                       |
| 4    | Sistema SGO           | Concatena los metadatos actuales junto con el `previous_hash`.  |
| 5    | Sistema SGO           | Calcula el nuevo hash criptográfico SHA-256 (`current_hash`).   |
| 6    | Sistema SGO           | Inserta el registro en la tabla `audit_logs`.                   |
| 7    | Sistema SGO           | El trigger de base de datos `prevent_audit_tampering` bloquea   |
|      |                       | cualquier sentencia posterior de `UPDATE` o `DELETE` en la tabla|
| 8    | Sistema SGO           | Concluye la persistencia del log de auditoría. Fin del caso.    |
+------+-----------------------+-----------------------------------------------------------------+

CURSOS ALTERNOS (Excepciones y Variaciones):
+------+-----------------------+-----------------------------------------------------------------+
| Ref. | Condición Detonante   | Secuencia de Acciones Alternas                                  |
+------+-----------------------+-----------------------------------------------------------------+

|      | manual de auditoría   |       la tabla `audit_logs` en PostgreSQL.                      |
|      | en base de datos      | 7a.2. El trigger dispara una excepción `RAISE EXCEPTION`:       |

|      |                       | 7a.3. La base de datos aborta la transacción maliciosa.         |

8. MATRIZ DE REGLAS DE NEGOCIO Y SEGURIDAD (RN-IA Y RN-AUD)
================================================================================

+-------------+----------------------------------------------------------------------------------+
| Código RN   | Descripción Formal de la Regla de Negocio y Seguridad                            |
+-------------+----------------------------------------------------------------------------------+
| RN-IA-01    | Principio de Aislamiento Absoluto de Solo Lectura:                               |
|             | El Asistente Conversacional Inteligente tiene terminantemente prohibido ejecutar |
|             | transacciones de escritura, actualización o borrado en la base de datos. Su pool |
|             | de conexiones opera exclusivamente con un usuario PostgreSQL con `GRANT SELECT`.|
+-------------+----------------------------------------------------------------------------------+
| RN-IA-02    | Delimitación Estricta por Roles (RBAC Guard):                                    |
|             | Las consultas en lenguaje natural formuladas por personal de mostrador (ACT-03) o|
|             | optometristas (ACT-02) que intenten extraer balances contables, ingresos totales |
|             | o contraseñas serán bloqueadas y reportadas en auditoría sin ejecutar consultas. |
+-------------+----------------------------------------------------------------------------------+
| RN-AUD-01   | Inmutabilidad Criptográfica de la Bitácora (Append-Only):                        |
|             | La tabla `audit_logs` es de solo adición (Append-Only). Toda fila insertada se   |
|             | encadena mediante un hash SHA-256 con el registro precedente, garantizando que   |
|             | cualquier borrado o modificación física en el motor sea detectada en peritajes.  |
+-------------+----------------------------------------------------------------------------------+

9. REQUISITOS DE CALIDAD Y SEGURIDAD ASOCIADOS (S-TAGS ISO/IEC 25010)
================================================================================

1. Subcaracterística de Autenticidad y Autorización (S-TAG-AUTH-05):
   - Verificación de roles en cada interacción del chat para impedir escalamiento de privilegios 
     mediante reescritura de intenciones léxicas.

2. Subcaracterística de Integridad Criptográfica (S-TAG-INT-08):
   - Encadenamiento criptográfico inmutable (Hash Chain) en la tabla `audit_logs` para 
     asegurar la inalterabilidad de los registros históricos de auditoría.

3. Subcaracterística de Responsabilidad y No Repudio (S-TAG-ACC-08):
   - Registro mandatorio del 100% de consultas realizadas al asistente y del 100% de 
     transacciones del sistema, blindando la responsabilidad legal de los operadores.
